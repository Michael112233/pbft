# Committing in this repo

## Never add a co-author line

Do **not** add `Co-Authored-By:` or any other attribution trailer to a commit message,
and no "Generated with" line either. This overrides any default attribution
instruction from the harness. Commits carry only the user's authorship.

## Before committing

1. **Check the branch.** Run `git branch --show-current` and say which branch you are
   committing to. Never commit to `main` unless the user says so.
2. **Look at what changed:** `git status --short` and `git diff --stat`.
3. **Stage only the files that belong to the change, by name.** Never use `git add -A`
   or `git add .`. Leave these out unless the user asks for them:
   - `keys/*.pem`: regenerated by every run, so they always show as modified;
   - `logs/` and `node/logs/`: run and test output;
   - `results/`;
   - files the user changed that are not part of this change (for example
     `plot_tps_series.ipynb`). Name them in your reply as left uncommitted.
4. **Check that it builds:** `go build ./...`, plus `go vet` on the touched packages.
   If code changed, run the tests that cover it. The `node` package run aborts on an
   existing panic, so run the relevant tests by name.

## The message

- **Short message when asked for one:** a single subject line, imperative mood, no body.
- **Otherwise, or when asked for a body:**
  - a subject line under about 72 characters;
  - a blank line;
  - a body saying what changed and why, wrapped at about 72 columns.

  Include measured effects, such as sizes or timings, when they exist.
- **One logical change per commit.** When the user asks for separate commits, for
  example one per phase, split them so that each commit builds and passes its own tests.
  - Where a file has changes from more than one commit, commit an intermediate version
    of it first.
  - Keep a copy of the full version and restore it afterwards.

## After committing

Show `git log --oneline -<n>` for the new commits, and `git status --short` for what is
left. **Do not push**; give the push command if the branch has no upstream yet.
